Architecture Context

## Stack

| **Layer**             | **Technology**                | **Role**                                                                              |
| --------------------- | ----------------------------- | ------------------------------------------------------------------------------------- |
| Mobile & Web Frontend | Flutter (Dart)                | Cross-platform client app handling UI, camera acquisition, and interactive rendering. |
| Backend Framework     | FastAPI (Python)              | High-performance asynchronous REST API serving inference endpoints and orchestration. |
| AI Inference Server   | ONNX Runtime / PyTorch Engine | Server-side execution runtime for Stage A, Stage B, and Stage C AI models.            |
| Auth & API Gateway    | Firebase Auth / Supabase Auth | User identity management, JWT validation, and secure route access control.            |
| Relational Database   | PostgreSQL / Supabase DB      | Structured storage for patient context, clinical notes, and inference metadata.       |
| Blob / File Storage   | AWS S3 / Cloud Storage        | Cloud storage for high-resolution raw ulcer photos, cropped ROIs, and mask files.     |

## System Boundaries

- `lib/` (Flutter Client) — Owns client-side camera capture, lighting/focus preprocessing, token management, interactive mask opacity rendering, and crop bounding box display.
- `app/api/` (FastAPI Server) — Owns HTTP request routing, JWT authentication checks, client image validation, payload serialization, and response assembly.
- `app/services/ai_pipeline.py` (AI Orchestrator) — Owns execution of the 3-model cascade (Stage A 3ch mask $\rightarrow$ Stage B 4ch refinement $\rightarrow$ ROI bounding box extraction $\rightarrow$ Stage C classification).
- `app/db/` & `app/storage/` — Owns database schemas, persistence operations for clinical reports, and secure image upload streams to S3 object storage.

## Storage Model

- **PostgreSQL Database**: Stores patient profiles, clinician metadata, evaluation timestamps, Stage C classification grades, confidence score arrays, recommendation texts, and S3 file paths.
- **Blob Storage (AWS S3)**: Stores raw captured images, generated Stage B binary mask PNGs, and auto-cropped region-of-interest (ROI) images.

## Auth and Access Model

- **Authentication**: Users authenticate via client-side Auth SDKs; every outgoing HTTP request carries a Bearer JWT in the `Authorization` header, validated by FastAPI middleware.
- **Role-Based Access**: Clinicians have read/write access to their assigned patient records and diagnostic reports. Admin accounts maintain system configuration and audit logs.
- **Data Isolation**: Patients and diagnostic records are strictly scoped by organization/clinic boundaries—no cross-clinic data leakage is permitted.

## Invariants

1. **Client Isolation from Intermediate Models**: The client application never receives or interfaces with Stage A outputs; Stage A operates strictly in-memory within the server pipeline.
2. **Transparent Classification Source**: Stage C classification must always run exclusively on the cropped ROI generated by Stage B's bounding box, and this exact ROI boundary must be returned to the client.
3. **Immutability of Historical Images**: Raw original photos, generated masks, and ROI crops saved to blob storage are immutable and cannot be overwritten once linked to a saved clinical report.
4. **Stateless AI Processing**: The AI pipeline backend must remain completely stateless; inference processing relies entirely on the payload and model parameters supplied per request.
